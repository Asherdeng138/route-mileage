# 里程记录（安卓）· 开发文档

> 面向开发者：设计取舍、计算规则、构建与测试。普通用户请看根目录的 [README](../README.md)。

公务用车里程记录 App：GPS 后台记录或手动补录 → 每月检查补全 → 按公司样板导出 **Word（.docx）** 和 **Excel（.xlsx）** 报销文件。PDF / CSV 只是补充格式。

技术栈：Expo SDK 58 · React Native 0.88 · Expo Router · expo-sqlite · expo-location + expo-task-manager（前台定位服务）· fflate（在手机上直接生成 docx / xlsx）· OpenStreetMap 图块（地图，不需要 Google API）。

## 月度导出（核心功能）

「报表」页的流程：

1. **选择月份**：显示选中行程数、里程、报销金额、本年累计，以及往月里程明细。
2. **检查**：每条公务行程都会做必填检查。缺起点或终点、只有坐标、仍在记录中、里程为 0 时会标红，**有红色问题就不能导出**。看起来像「家 ↔ 固定办公室」通勤的行程会标黄，需要你确认。点行程可以直接去修改。
3. **选择导出范围**：默认选中未报销的行程，已报销的行程会显示报销日期。空月份会明确提示，不能导出。
4. **生成 Word + Excel**：两个文件来自**同一份报销快照**。快照保存在数据库里，状态为「已导出，未确认」。
5. **分享或保存**：可以分别分享 Word / Excel（调起系统分享），也可以「两个文件保存到文件夹…」（系统文件夹选择器，可选下载目录或 Google Drive）。PDF / CSV 是补充格式，用的也是同一快照。
6. **确认已报销**：这是单独的一步。导出文件不等于已报销。确认后快照被锁定，之后修改费率或行程，都不会改变这份报表。可以撤销确认。每次导出的记录都能「重新生成此快照」，得到完全相同的文件。

文件名：`Mileage-Claim-YYYY-MM.docx`、`Mileage-Details-YYYY-MM.xlsx`。

### 样板解析结果

`example/` 里有 3 个 Word 和 3 个 Excel（公司内部样板，文件名是 UUID，**不包含在公开仓库中**），都已经实际解析过。

| | Word 样板 | Excel 样板 |
|---|---|---|
| 页面 | A4 纵向，页边距 2.54 cm（1440 twip），没有页眉页脚和签名栏 | 单表 `Sheet1`，页边距 0.7/0.75 英寸 |
| 结构 | 不是表格，而是段落：标题、费率说明、Miles total、Amount to claim、Takes me to … miles this year，然后每条行程一段描述加一张路线截图 | A1 标题；A2:C2 `Date / Miles / Cost`；明细行；费率说明；`Miles in <月>` 求和；往月里程；`Takes me to miles this year` |
| 字体 | 主题字体 Aptos 12pt，标题段落粗体 | Aptos Narrow 11，标题和表头粗体，细边框，A 列换行 |
| 格式 | 日期 `2026/09/01`，里程 `66.5 miles` | 金额格式 `"£"#,##0.00`，公式 `=B3*0.45`、`=SUM(B3:Bn)` |

导出时**原样复用样板的 styles / theme / fontTable / settings**（`scripts/extract-template-parts.py` 生成 `src/export/templateParts.ts`），Excel 单元格样式编号也与样板一致。样板里的示例人物、行程和金额不会被复制。

样板正文没有姓名、部门、车牌等栏位，所以没有设为必填。设置里的「姓名 / 公司」只写入文件属性。

### 金额与舍入（三处一致）

- 每条行程的里程先四舍五入到 0.1 英里。
- 行程金额用精确整数表示（单位是千分之一便士），等于 Excel 公式 `=B*0.45` 的精确值，行内不单独取整。
- 月度合计是各行精确金额之和，最后四舍五入一次到便士，与 Excel `SUM` 后按 `£0.00` 显示的结果相同。
- 和样板一样，单行显示金额相加，可能与合计差 1 便士。

### 排版处理

- 行程越多，表格行越多：`SUM` 范围、打印区域（`Print_Area`）、重复表头（第 1–2 行）、`dimension` 都会自动调整。打印设置为 A4、适合页宽。
- 长地址和中英文混排：Excel A 列自动换行并估算行高（中文按双宽计算），Word 自动换行。
- Word 每条描述都设为「与下段同页」，图片宽度不超过版心，高度不超过约 16.5 cm，所以描述和图片不会被拆到两页，也不会被截断。
- Excel B 列从样板的 5.27 加宽到 8.73。原宽度下，四位数里程（例如 1234.5）会被 Excel 显示成 1235。

## 费率

- **公司报销费率**：依据样板，前 10,000 英里 £0.45，超出部分 £0.25，每个累计年度重新计算。费率保存为**带生效日期的版本**（设置 → 公司报销费率 → 管理）。修改费率时新增一个版本，生效日之前的行程不受影响；已确认报销的快照永远不变。
- **HMRC 参考标准（仅展示，不参与计算）**：gov.uk「Travel – mileage and fuel rates and allowances」页面（2026-05-21 更新，2026-10-21 核对）中，汽车 / 厢式货车 2026/27 税年起是 **55p / 25p**，2011/12–2025/26 是 45p / 25p。之前交接里写的“HMRC 55p”只适用于 2026/27 税年起，并不是公司费率。App 不做税务判断。
- **本年累计口径**：默认按税年（4 月 6 日起），可以改为自然年。开始使用 App 之前的月份，在「设置 → 往月里程」录入（例如 7 月 520.4、8 月 498.7）。只导出某个月份时，累计不会丢失之前的月份。

## 地图（Google 原生地图 / OpenStreetMap）

- **App 内地图（1.4.0 起默认 Google）**：构建时如果有 Key（`.secrets/google-api-key.txt` 或环境变量 `GOOGLE_MAPS_API_KEY`），Key 会打包进安卓清单，记录页和行程详情显示 Google 原生地图（`react-native-maps`）：蓝色轨迹带白边、绿色起点、红色终点，记录中显示 Google 蓝点并跟随；拖动地图后暂停跟随，点右上角 ◎ 恢复。
  - 安卓上的 Maps SDK 地图加载**免费、不限次数**，不计入每月 1000 次地点查询。
  - Key 的「API 限制」必须同时勾选 **Maps SDK for Android** 和 Places API (New)；「应用限制」为 Android 应用 `com.mia.routemileage` + 私有签名 SHA-1。没勾选时地图是灰色空白（轨迹数据不受影响），可在「设置 → 记录与地图」改用 OpenStreetMap。
  - 没有 Key 的构建自动使用 OpenStreetMap，不会加载 Google 地图模块。
- **Word 里的路线图始终用 OpenStreetMap**（Google 地图的截图不允许这样放进文件，且需要付费的 Static Maps API）。
- **OpenStreetMap 地图**：显示 OSM 底图和实际轨迹，跟随最新位置，可以 ＋/－ 缩放。
- **自动路线图**：结束记录后，App 在后台生成一张 960×720 的路线图（真实地图 + 实际 GPS 轨迹 + 起终点），保存在手机里，导出时放进 Word。行程详情页可以「重新生成」。
- **没有网络时**：轨迹照常记录和显示，只是没有底图。路线图标记为「等待联网生成」，下次打开 App（每次最多补 3 条）或导出时会再试；仍失败时，Word 使用轨迹预览图。
- **只按实际路线**：每次都画这一趟真正走过的路线，同一目的地走不同的路，图和里程也不同。没有做「常用路线里程复用」。
- **遵守 OSM 图块使用政策**（https://operations.osmfoundation.org/policies/tiles/ ，2026-10-21 核对）：
  - 只使用 `https://tile.openstreetmap.org/{z}/{x}/{y}.png`；
  - 请求带本 App 的 User-Agent；
  - 地图和图片上标注 "© OpenStreetMap contributors"（App 内可点开版权页）；
  - 遵守缓存头，至少缓存 7 天，过期后发条件请求；
  - 同时最多 4 个请求；
  - 只下载正在看的范围（一张路线图约 20 个图块），不预先下载区域，不做离线地图。
  - 这是社区免费服务，没有可用性保证。图块地址集中在 `src/lib/osm.ts`，以后可以换成自建或其他服务。
- **隐私**：显示地图时，会向 OpenStreetMap 服务器请求你所在区域的图块（对方能看到大致区域），**不会上传轨迹**。不想联网时，在「设置 → 在线地图（OpenStreetMap）」关闭，改为只显示无底图的轨迹预览。
- 路线图文件和截图一样存在手机里，不包含在 JSON 备份中。换手机恢复备份后，打开行程或导出时会重新生成路线图。

## 行驶路径（像导航一样的路线）

- 记录时，手机 GPS 行驶中大约每 8 秒记一个点（1.4.0 起；之前每 5 秒），全程连续记录。路线图就是把这些点按顺序连起来，所以转弯、路口、环岛都会按实际走的路显示。**不需要 Google**，也不需要网络（没有网络时只是没有地图底图）。
- 2026-10-24 在模拟器上验证：用一条真实道路（Farnborough 市中心 → Frimley Green，2.66 英里）按每秒一个点回放，期间锁屏 90 秒。App 记录了 68 个有效点（平均每 6 秒一个），路线沿道路完整显示，GPS 里程 2.55 英里。
- 什么时候会出现「直线」：两点之间长时间没有定位，这一段只能直线连接。常见原因：
  - 定位权限只给了「大致位置」（安卓 12+）：误差几百米的点会被过滤掉。现在开始记录时会检测到并提示打开「使用确切位置」，记录页也会显示警告。
  - 手机省电策略限制了后台定位：在电池设置里把本 App 设为「不受限制」。
  - 隧道、地下停车场：属于正常情况。
- 行程详情的地图下方会显示「路线由 N 个 GPS 点连成，平均每 X 秒一个点」。有定位中断时会列出中断时长和按直线连接的比例（`src/lib/trackQuality.ts`）。
- 没有做「道路吸附」（把点自动贴到道路上）：那需要把整条轨迹发到第三方服务器（例如 OSRM）。在定位正常的情况下，原始轨迹已经沿着道路走。

## 省电（1.4.0）

实测耗电大以后做的优化（2026-10-24 经用户同意），参数集中在 `src/lib/trackingConfig.ts`，停车判定是纯函数 `src/lib/stillness.ts`（`tests/stillness.test.ts`）：

| # | 优化 | 说明 |
|---|---|---|
| 1 | 忘记结束时自动处理 | 停留 10 分钟发通知提醒；停满 20 分钟自动结束并保存，结束时间取**开始停留**的时刻，然后发通知。「设置 → 记录与地图」可改为 15/30/60 分钟或关闭（关闭后仍提醒一次） |
| 2 | 停车自动低功耗 | 停住 2 分钟（离停车点 40 米以内、速度 < 3 m/s）切到 Balanced 精度、30 秒一次；离开 150 米（或 2×精度）或速度 > 3 m/s 立刻切回高精度 |
| 3 | 后台批量 | App 在后台 / 锁屏时，系统每 60 秒（低功耗时 30 秒）把攒下的点一次交给 App，减少唤醒 |
| 4 | 界面刷新 | 记录页 5 秒刷新、权限 30 秒检查一次；首页和记录页在后台完全不刷新 |
| 5 | 采样 | 行驶中每 8 秒一个点（原 5 秒 / 10 米） |

注意：
- 采样**不设最小距离**：安卓设了最小距离后，停车时系统完全不回调，停车判定就没法工作。GPS 在两种设置下都开着，停车时多几次回调几乎不耗电，2 分钟后就切到低功耗。停车时的点会被里程过滤掉，不入库。
- 从低功耗恢复的头 30–60 秒，可能按直线补算一小段（通常几十到一两百米）。
- 在后台切换低功耗需要定位权限「始终允许」。只给了「仅使用时允许」时保持高精度（更耗电，但记录不受影响）；回到 App 前台时会自动补上切换。
- 停车判定状态只保存在内存里；App 进程被系统杀掉后重新开始计时（不会误判）。
- 2026-10-24 模拟器验证（release 1.4.0，Google 地图）：沿真实道路回放 2.66 英里，记录 2.58 英里；到达后停车约 2.5 分钟显示「停车中 · 省电定位」；锁屏状态下第 7 分钟收到提醒（自动结束设为 15 分钟），第 15 分钟自动结束并保存，行程结束时间是停车时刻。**真机耗电对比尚未测量。**

## 界面风格（1.3.0）

参照 Apple 人机界面指南：
- 浅灰分组背景加白色圆角卡片，没有描边；
- 系统蓝作为操作色，系统红、绿、橙表示状态；
- 页面大标题（34 号粗体），iOS 式分段控件，绿色开关；
- 行程列表为「标题 + 灰色副标题 + 右侧数值 + ›」的列表行，只在需要时显示一个状态（缺起终点 / 已报销 / 私人）；
- 导航栏与背景同色、无阴影，返回箭头为系统蓝。

颜色和字号集中在 `src/constants/theme.ts`，组件在 `src/components/ui.tsx`，深色模式使用对应的 iOS 深色系统颜色。安卓上使用系统字体（Roboto / 思源黑体），不使用 Apple 的 SF 字体（授权限制）。

## GPS 记录

- 流程：开始 → 后台持续记录（通知栏常驻「正在记录行程」）→ 结束 → 补全起终点、途经地点、截图 → 保存。
- 防重复：连续点「开始」不会生成多条记录中的行程，开始、结束、继续三个操作会串行执行。
- 权限：
  - 先申请「使用时」定位，并说明需要「始终允许」，再跳转系统设置页（安卓 11+）。
  - 安卓 13+ 申请通知权限。
  - 权限被拒绝或永久拒绝时，提示并提供「打开设置」。
  - 定位服务关闭时，弹出系统对话框请你打开。
- 记录页（1.4.0 重新设计）：上方大地图，下方卡片显示大号里程和用时、定位状态，一个大的红色「结束记录」按钮；「放弃记录」和「后台记录与省电说明」在按钮下方。
- 记录页只在 App 前台时刷新：轨迹每 5 秒（只增量读取新点）、权限每 30 秒、计时每秒；锁屏或切到导航时全部停止。需要处理的问题一次只显示一条最重要的：
  - 定位权限被撤销 / GPS 关闭；
  - 后台定位被系统停止（可「继续记录」）；
  - 只给了「大致位置」；
  - 超过 90 秒没有定位（暂时丢失）；
  - 「仅使用时允许」或通知被关闭。
- 离线：坐标和里程照常记录。地址解析失败时保留坐标，标记为「地址未解析」，可以「重试」或手动填写，App 打开时也会自动重试。**坐标文本不会再被当成地址写进报表。**
- 意外中断（App 被杀或手机重启）后再打开 App，会弹窗「继续记录 / 结束并保存」。
- 过滤阈值集中在 `src/lib/trackingConfig.ts`：
  - 精度差于 50 m 的点丢弃；
  - 原地漂移阈值为 max(15 m, 0.8×精度)，上限 35 m；
  - 低速（报告速度或平均速度 < 0.8 m/s）且位移小于 3×精度时，视为停车漂移；
  - 隐含速度大于 70 m/s 视为跳点，信号中断超过 120 s 后不做跳点检查。
  - 下一个点总是和「上一个被接受的点」比较，慢速行驶时不会丢里程。测试结果：正常驾驶误差 ±3% 以内，拥堵慢行在 −7%/+5% 以内，停车 30 分钟漂移小于 50 m。

**支持边界（不承诺永远后台运行）**：
- 在系统里「强制停止」App，或手机重启后，定位会停止，直到你重新打开 App。中断期间没有轨迹，恢复后中断两端之间按直线计入。
- 部分厂商（华为、小米、OPPO、vivo、三星等）的省电策略可能杀掉后台服务，需要把本 App 的电池设置设为「不受限制」并允许自启动。App 内「后台记录说明」有逐项指引。

## 数据与备份

- 数据只存在手机本地 SQLite，不需要账号，不会上传。
- 数据库按版本迁移（`PRAGMA user_version`），每一步迁移都在事务里执行，失败时回滚，旧数据保留。v1 → v2 迁移会：
  - 给旧的手动往返行程补上单程里程；
  - 把旧版默认的 55p（来源未核实）替换为样板费率 45p。如果你以前手动保存过其他费率，会保留为一个单独版本并提示核对。
- 备份是带格式版本和数据库结构版本的 JSON，包含行程、轨迹、地点、设置、费率版本、报销快照和往月里程。
- 导入前会校验结构、id 是否重复、轨迹点和行程的关联、日期格式等。之后由你选择：
  - **合并**：保留现有数据，只添加备份中没有的行程和地点，重复的行程会跳过；
  - **覆盖**：先自动把当前数据备份到 App 内部，再替换。
- 整个导入在一个事务中完成，失败时全部回滚，不会留下半套数据。
- 也兼容旧版（v1）备份文件。

## 信号中断补算（1.6.0）

乡村、隧道、树林里 GPS 可能一段时间没有可用的点，两端之间只能按直线计入，里程偏少。1.6.0 起：

- **什么时候补算**：两个相邻 GPS 点之间断开 ≥ 60 秒、直线距离 ≥ 300 米（`trackingConfig.GAP_FILL`）。
- **怎么补算**：行程结束后（没网时下次打开 App）用 Google Routes API 查这两点之间的驾车路线（推荐路线 + 最多 3 条备选），**选预计用时最接近实际断开时间的那条**（2026-10-24 与用户确认的方案 1：最可能是真实走的路，不会系统性偏多）。
  - 只考虑来得及开完的路线：预计用时 ≤ 断开时间 × 1.25 + 60 秒，平均速度 ≤ 90 mph，长度不短于直线；
  - 断开时间超过最长可行路线用时 2 倍（中途多半停过车）：用 Google 推荐路线，不选绕远的；
  - 没有可行路线：保持直线，行程详情提示「请核对里程」。
- **里程**：增加 =（路线长度 − 已计入的直线），自动计入申报里程；GPS 实测里程单独保留。手动修正过里程的行程不改申报里程；**已报销的行程不再改动**。
- **显示**：地图（App 内 Google / OSM 地图和 Word 路线图）上补算路段为浅蓝虚线；行程详情显示「已补算 N 段：+X mi」，可以「撤销补算」/「重新补算」；以前的行程可以手动「按 Google 路线补算」。Word 图注写明 “plus X miles for GPS signal gaps, measured along the Google Maps driving route”。
- **费用**：Routes API Compute Routes Essentials 每月免费 10,000 次（之后 $5 / 1000 次，2026-10-24 核对）。每段中断 1 次，App 内上限每月 1,000 次（与地点查询分开计数），超过后按直线计算。
- **需要你在 Google Cloud 做的**：启用 Routes API，并在 Key 的「API 限制」里勾选 Routes API（与 Places API (New)、Maps SDK for Android 并列）。建议把 ComputeRoutes 每日配额设为 100 左右。检查：`npx tsx scripts/check-routes.ts`。
- 设置 → 记录与地图 →「信号中断时按 Google 路线补算」可以关闭。
- 代码：规则 `src/lib/gaps.ts`，存储 `src/db/gaps.ts`（迁移 V6：`trip_gaps` 表、`trips.gap_fill_m / gap_fill_status`），查询 `src/services/gapFill.ts`，测试 `tests/gaps.test.ts`。

## 归档与自动删除（1.5.0）

```
已报销 ──归档──▶ 已归档 ──30 天──▶ 最近删除（可恢复）──30 天──▶ 永久删除
```

- **归档**：只有已报销的行程可以归档。报表里「确认已报销」后会问是否归档这次导出的行程；导出记录卡片上也有「归档这 N 条行程」；单条行程详情里有「归档」。归档后不在行程列表、首页最近行程和报表选择列表里显示，在「行程 → 已归档 · 最近删除」（或「设置 → 数据 → 归档与最近删除」）查看，可以取消归档。
- **最近删除**：归档满 30 天自动移到这里；你手动删除的行程也先进这里（以前是立即删除）。30 天内可以恢复（回到行程列表）。
- **永久删除**：在最近删除满 30 天后，打开 App 时执行。轨迹点、起终点、地址、事由、备注、截图和路线图文件全部删除。
  - 已报销的公务行程只保留**日期、时间、里程**（没有任何地点信息），界面上不显示，只用于本年累计和 10,000 英里分档——否则删掉 4 月的行程会让之后的行程从 25p 错算回 45p。
  - 未报销的行程（包括私人行程）整条删除，也不再计入累计。
- 计时以打开 App 时为准：很久没打开 App 时，移到最近删除的时间按那次打开算，保证仍有完整 30 天可以恢复。
- **报销快照（报表 → 导出记录）不会删除**，可以随时重新生成当月 Word / Excel；已永久删除的截图和路线图不会再出现在重新生成的 Word 里。
- 撤销「已报销」会同时取消归档；已永久删除的行程保持已报销（只剩里程）。
- 备份文件包含归档状态；恢复旧备份时，所有行程都是未归档状态。
- 代码：规则 `src/lib/archive.ts`，数据库 `src/db/archive.ts`（迁移 V5 增加 `archived_at / deleted_at / purged_at`），测试 `tests/archive.test.ts`。

## 起终点附近地点（Google Places，每月限额 + 自动切换免费来源）

**作用**：开始记录时和结束记录时，自动识别起点、终点附近有名字的地点（门店、公司、机场…），作为起终点名称，不用自己搜地址。行程里的起点、终点都有「📍 在地图上选 / 附近地点」：
- 像 Uber 选上车点一样，拖动地图，让中心图钉对准位置；
- 松手后，下面列出附近地点（含距离和类型），点一下就填入；
- 也可以直接选「使用图钉位置」，填入街道地址。

**来源顺序**（`src/services/nearby.ts`）：
1. 常用地点：免费、离线；
2. Google Places API (New) Nearby Search：已启用、填了 Key、本月没到上限时使用；
3. OpenStreetMap Overpass：免费，在 Google 不可用、已到上限或出错时使用；
4. 手机自带地址解析：给出街道地址。

**费用控制**：
- 价格依据 Google 官方价格页（2026-10-24 核对）：Nearby Search **Pro** 每月免费 5,000 次，超出后 $32 / 1000 次；Enterprise 档只有 1,000 次免费。App 只请求 Pro 档字段（名称、地址、坐标、类型），不请求评分、营业时间、电话，测试中有断言保证这一点。
- **App 内硬上限**：每月默认 1,000 次，可在设置中调整，范围 0–5,000。每次调用 Google 之前先在数据库里「预约」计数，并发调用也不会超过上限。到达上限后，本月不再调用 Google，自动改用 OpenStreetMap 和手机地址解析；下个月自动恢复。月份按太平洋时间计算，和 Google 的计费月一致，不会提前重置。
- 预计用量：每趟行程约 2 次（开始 1 次、结束 1 次；如果起终点匹配到常用地点，就不调用 Google），拖动选点时每次停下 1 次。同一位置在本次打开 App 期间只查一次。
- **Google 侧保险**（App 内上限只管得住这部手机）。「设置 → Google 地点」页里有分步说明：
  - API 限制只勾选 Places API (New)、Routes API（信号中断补算）和 Maps SDK for Android（App 内地图用）；
  - 在 Quotas 里把每日请求数限制到 50 左右；
  - 设置预算提醒。
  - 按网上开发者的反馈，「Android 应用」类型的 Key 限制对这种直接 REST 请求不一定生效，所以主要依靠 API 限制加每日配额。
- **Key 保存**：在 App「设置 → Google 地点」里粘贴保存，存放在手机的加密存储（expo-secure-store）中，不进代码、不进备份、不上传。也可以构建时在 `.env` 写 `GOOGLE_MAPS_API_KEY`（不要提交）。
- Word 路线图仍然使用 OpenStreetMap，不产生 Google 费用。构建时提供 Key（`.secrets/google-api-key.txt`），App 内显示原生 Google 地图（安卓地图加载免费），同一个 Key 也用于地点查询。
- 检查免费来源：`npx tsx scripts/check-overpass.ts <纬度> <经度>`。

## 构建 APK

在 Windows 上本地构建（不需要 Expo 账号或付费云构建）：

| 文件 | 大小 | 适用 |
|---|---|---|
| `dist/RouteMileage-1.6.1-arm64.apk` | 50 MB | 近年绝大多数安卓手机（64 位 ARM），推荐 |
| `dist/RouteMileage-1.6.1-universal.apk` | 121 MB | 所有 CPU 架构（含旧 32 位手机、模拟器） |

- 包名 `com.mia.routemileage`，版本 1.6.1（versionCode 10），目标 SDK 36。**从 1.2.0 起使用私有签名密钥**（见下节）；1.1.1 及以前使用公开的调试签名。
- 权限只有：定位（含后台）、前台定位服务、通知（含开机广播，来自 expo-notifications）、网络等基础项。1.4.0 起构建时会把 `.secrets/google-api-key.txt` 里的 Key 打包进 APK（Google 地图需要）。依赖库带入的摄像头、麦克风、悬浮窗、写存储权限用不到，已在 `app.json` 的 `blockedPermissions` 中屏蔽。
- 工具链：Node 24、JDK 17、Android SDK（platform 37、build-tools 37.0.0、NDK 27.1、CMake 3.31.6）。首次运行脚本时需要阅读并接受 Android SDK 许可。新版 cmdline-tools 用 `android` 命令代替了 `sdkmanager`，安装时加了 `--no-metrics`，不上报使用数据。
- Windows 上的坑：CMake 3.22.1 自带的 ninja 1.10 不支持长路径，编译 gesture-handler 时报 “Filename longer than 260 characters”。改用 CMake 3.31.6（自带 ninja 1.12.1），在 `android/local.properties` 里用 `cmake.dir` 指定。

重新构建（脚本会安装 SDK 组件、执行 prebuild、写好 `local.properties`、运行 Gradle）：

```
npm run build:apk
```

**公开下载用的安装包**：`npm run build:apk:public`（`-Public`）。设置 `ROUTE_PUBLIC_BUILD=1`、用 `prebuild --clean` 重新生成原生工程，不打包任何 Google Key（地图用 OpenStreetMap，用户可在 App 里填自己的 Key）；构建后逐个读取 APK 里的文件（含 UTF-16 的二进制清单），发现 `AIza…` 就报错，不允许发布。公开包和个人包签名相同，可以互相覆盖安装。

只构建 arm64 版：在 `android` 目录运行 `gradlew.bat assembleRelease -PreactNativeArchitectures=arm64-v8a`。产物在 `android\app\build\outputs\apk\release\app-release.apk`。

**安装**：把 APK 传到手机（数据线、邮件附件或网盘），在手机上点开安装，按提示允许「安装未知来源应用」。

测试中发现并修复的问题：
1. **release 版启动闪退**：Expo 模板默认对 release 版开启 R8 代码压缩，AGP 9 的完整模式会改掉 WorkManager 内部 Room 数据库类的名字，App 一启动就崩溃。已通过 `expo-build-properties` 关闭 release 版压缩，并加上 Room 保护规则（写在 `app.json` 中）。APK 体积因此略大。
2. **强制停止或重启后不提示、也无法真正继续**：expo-task-manager 会持久保存任务注册，`hasStartedLocationUpdatesAsync` 仍返回「在运行」，但定位服务其实已停止。改为同时判断「本进程是否启动过定位」；继续记录时先清掉残留注册，再重新启动。
3. 首页「已行驶」只在进入页面时刷新 → 记录中每 5 秒刷新一次。
4. 底部导航只有当前页显示文字 → 四个标签都显示文字。
5. 安卓不允许把「下载」根目录选为保存文件夹 → 导出页提示选择 Documents 或新建文件夹。

模拟器无法验证的：真实 GPS 信号质量、厂商省电策略、长时间（几小时）记录、真实网络环境下地图加载速度。

4. 打开**飞行模式**（关闭网络但保持 GPS）开一段，确认仍在记录。结束记录后，行程显示「地址未解析」；恢复网络后点「重试」，或手动填写。
5. 记录中从多任务界面划掉 App，再重新打开，应该弹出「继续 / 结束并保存」。
5a. 省电：到达后不点结束，停车 10 分钟应收到「看起来已经到达」通知，20 分钟收到「行程已自动结束」，行程结束时间是停车的时刻。对比一趟 1 小时的行程在 1.3.0 和 1.4.0 的耗电（系统设置 → 电池 → 应用耗电）。
6. 结束记录：核对起点 / 途经 / 终点、申报里程与 GPS 里程。确认行程详情显示「Word 路线图：已生成」（也可以改为附加自己的截图），然后保存。
7. 报表 → 选择本月 → 修正红色问题 → 生成 Word + Excel → 分享到邮箱，或保存到文件夹 → 在电脑上用 Word / Excel 打开，和样板对照 → 回到 App「确认已报销」。
